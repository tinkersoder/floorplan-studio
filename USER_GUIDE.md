# Floorplan Studio — User Guide

This guide walks through the three things you'll actually do: **connect Home Assistant**
(optional), **design a floorplan**, and **add the export to a dashboard**.

---

## 1. Connect Home Assistant (optional)

The app is fully usable offline with a built-in demo entity set — you only connect to pull
your real entities and see live states.

1. Click the **HA** button in the top-right.
2. Enter your **Home Assistant URL** (e.g. `http://homeassistant.local:8123`) and a
   **long-lived access token** (HA → your profile → **Security** → *Long-lived access
   tokens* → *Create token*).
3. Click **Test connection & connect**. On success you'll see how many entities loaded and
   the entity list on the left switches from `demo` to `live`.

**If it fails:**

- **Mixed content** — a `http://` HA URL is blocked from a page served over `https://`.
  Serve this app over `http`, or put HA behind `https`. Easiest fix: host the app *inside*
  HA (`/config/www/floorplan-studio/`) so both share an origin.
- **CORS** — add this app's origin to HA's `configuration.yaml`, then restart HA:
  ```yaml
  http:
    cors_allowed_origins:
      - http://localhost:5178      # or wherever you serve the app
  ```
- **Auth failed** — regenerate the long-lived token and paste it again.

Your token is stored only in this browser (localStorage) and is only ever sent to your own
HA instance. Click **Disconnect** to wipe it and return to demo mode.

## 2. Design a floorplan

### Background
- In the right panel click **Upload image…**, or **paste** (Ctrl/Cmd+V) / **drag-drop** an
  image onto the canvas. A photo, 2D plan, or 3D render all work.
- Adjust **opacity**, **scale**, **X/Y position** and **rotation**. Set the **canvas size**
  if you want a specific aspect ratio. Tick **Lock background layer** when you're happy so
  you don't nudge it while editing.

### Markers (entities)
- Click any entity in the left list to drop a marker, or type an `entity_id` at the bottom
  and press **Add**. Search and filter by domain to find things fast.
- Select a marker to edit it on the right:
  - **Entities** — add more than one entity to a single marker; for ha-floorplan set a
    **Group element id** (e.g. `living_lights`) so several lights share one marker.
  - **Style** — MDI icon / dot / state label / image / custom SVG, plus colour and size.
    Tick *Show live state value + unit* to display a sensor's reading.
  - **State-based styling** — add rules to change colour/icon/animation by state
    (on/off, a numeric threshold, a gradient heatmap, or an exact string match).
  - **Conditional visibility** — show the marker only when an entity is on / equals a state.
  - **Actions** — tap / hold / double-tap → toggle, more-info, call-service (with a
    service + YAML data editor), navigate, or url.
- **Drag** to position, **marquee-select** or Shift-click for multi-select, **arrow keys**
  to nudge (Shift = ×10), **Ctrl/Cmd+D** to duplicate, **Del** to delete.

### Rooms
- Pick the **Room** tool (`R`), click to add polygon points, then **double-click** or press
  **Enter** to finish. Select the room to set its **name**, **HA area**, **fill + opacity**,
  **state-based colouring** (e.g. tint by a light, motion sensor, or temperature gradient),
  and a **click action**.

### Walls, doors, windows
- **Wall** tool (`W`) — click along the wall; angles snap to 15° (toggle in the background
  panel). Double-click / Enter to finish. Style thickness + colour when selected.
- **Door** / **Window** tools — click near a wall to snap an opening onto it.

### Layers & floors
- The **Layers** panel toggles visibility 👁 and lock 🔒 for background / walls / rooms /
  entities / labels.
- **Floors** — add floors with **＋**; each floor has its own background and content. Double
  click a floor tab to rename.

### Preview
- Toggle **Preview** in the top bar to see your rules driven by live states (or the demo
  set). Toggle back to **Edit** to keep working.

### Import a floorplan card already in Home Assistant

**Import card** (toolbar) brings an existing dashboard floorplan back into the editor — a card you
exported from Floorplan Studio earlier, one generated by Ramses Extras' floorplan helper, or a
hand-made ha-floorplan / picture-elements card.

1. **Scan dashboards** (needs the Home Assistant link) reads every dashboard and lists each
   `custom:floorplan-card` and `picture-elements` card, including ones inside stacks, sections and
   conditional cards. Or paste YAML — a single card, a view or the whole raw dashboard config.
2. Pick a card, choose **New project** or **New floor in this project**, and import.
3. Files the card references are fetched from Home Assistant: `/local/…` (public) and uploaded
   images under `/api/image/serve/…` (sent with your token). Inline `data:` images need no
   download. If a download is blocked (CORS from a standalone app, or no HA link), use
   **Add files…** — files are matched to the card's references by file name. A split-out
   ha-floorplan `config: /local/…yaml` and its `stylesheet` are loaded the same way.

What you get:

- **ha-floorplan**: every element a rule binds (`element:` or the entity id) becomes a marker at
  its rendered centre, with its entities and tap / hold / double-tap actions. Studio exports also
  get their icon, colour, label and state rules back; Ramses Extras markers keep their icon, colour
  and device name. Sizeable closed shapes become rooms; `area.<id>` elements become rooms carrying
  that **HA area** (so the RAMSES import drops devices straight into them) and `room_*` elements
  (Studio exports) keep their names. Everything else in the drawing becomes the floor background,
  with the converted elements removed so nothing is drawn twice (toggleable). Rules whose element
  isn't in the SVG can be parked in a row along the bottom.
- **picture-elements**: the image becomes the background (canvas = image size) and each positioned
  entity element a marker (`state-label` → live label, conditional elements → marker visibility).

### Import devices (registered integrations)

The **Devices** toolbar button opens the generic device importer. The sources it lists come from
integrations registered through the [plugin API](#plugin-api-for-integrations) — Floorplan Studio
ships a bundled RAMSES RF source described below; other integrations (yours?) can register their own.

1. Draw a room for every space and set its **HA area** in the Inspector (or give the room the same
   name as the HA area). This is how devices find their room.
2. Click **Devices** in the toolbar and pick a source (needs the Home Assistant link — token or
   dashboard-card mode).
3. Or **paste / load** whatever a source recognises offline — the modal tries each registered
   source's parser, and a raw studio project JSON merges without one.

**Bundled source: MQTT** (`src/examples/ha-devices.ts`) — lists every device in the HA registry, grouped by integration
via the HA entity registry. It exists as the **reference implementation** for the plugin
API, not as an integration play: real integrations ship their own provider as a Lovelace
resource (see below).

**RAMSES RF / Ramses Extras** — for evohome / RAMSES-II systems run through
[Ramses RF](https://github.com/ramses-rf/ramses_cc) (`ramses_cc`),
[Ramses Extras](https://github.com/wimpie70/ramses_extras) ships its own provider
(`ramses-studio-provider.js`, auto-registered by the integration):

- **RAMSES RF / Ramses Extras** (live) — with **Ramses Extras** installed it calls
  `ramses_extras/floorplan_helper/get_topology`, which already resolves zones, parent links,
  display names and each device's primary entity; without Extras it rebuilds the same list from
  the HA device/entity/area/floor registries, filtered to `ramses_cc` (reading both `via_device_id`
  and the HA 2026.9+ `parent_device_id` for parent links).
- Offline **paste / load**: a saved `get_topology` result (raw or wrapped in the WebSocket
  `result`), the response of the Extras service `ramses_extras.floorplan_seed_studio` (or any
  studio project JSON) — its markers and missing rooms are **merged** into the current project,
  scaled to this canvas — or a ramses_cc `known_list`, ramses_rf schema or packet log: every device
  id (`04:123456`, zones `01:123456_02`) is matched to your HA entities.
4. Review the table: tick devices (gateways are off by default), choose labels, extra entities
   (temperature, heat demand, CO₂…), ready-made **state rules** (offline grey, battery-low blink,
   window-open icon, heat-demand gradient) and marker size. Each row shows where the device goes:
   *room*, *staging row* (bottom edge of the floor matching the area's HA floor, else the active
   floor) or *already on plan*.
5. **Add markers**. The whole import is one undo step, and running it again only adds devices that
   aren't on the plan yet.

Icons follow the device class: zone `home-thermometer`, TRV `radiator`, controller `thermostat`,
FAN `fan`, remote `remote`, CO₂ `molecule-co2`, relay `pipe-valve`, gateway `router-wireless`…
Heating devices are orange, ventilation blue.

### Saving
- Everything **autosaves** to your browser. Use **Projects** to create/open/delete projects,
  **Export current as JSON** for a backup, or **Import JSON…** to restore one.

## 3. Add the export to a dashboard

Open **Export** (top-right). Choose a target, choose how the background image is handled,
then **Copy YAML** (or **Download files**).

**Background image mode (both targets):**
- **Embed** *(default)* — the image is inlined as a base64 data URI. The card is fully
  self-contained; nothing else to copy.
- **Reference** — the card points at `/local/floorplan/<name>.png`. Also download the
  files and drop the `.png` (and `.svg` for ha-floorplan) into your HA
  `/config/www/floorplan/` folder (served at `/local/floorplan/`).

### Path A — ha-floorplan (rooms + rich rules)

Best when you want filled polygon rooms and rich state colouring.

1. **Install the card**: HACS → *Frontend* → search **floorplan** → install → **restart HA**.
2. In Export, pick target **ha-floorplan**, leave **Embed** selected.
3. Click **Copy YAML**.
4. In your dashboard: **Edit dashboard → Add card → Manual**, paste, **Save**.
5. (If you chose **Reference** instead, also copy the downloaded `.png` + `.svg` into
   `/config/www/floorplan/`.)

The generated card is a `type: custom:floorplan-card` with an `<image>` background, one
`<g id="…">` group per marker, `floorplan.class_set` rules for on/off colouring,
`floorplan.style_set` for thresholds/gradients, and `floorplan.text_set` for sensor
values — the structure ha-floorplan expects, so it renders immediately.

### Path B — Picture Elements (native, no HACS)

Best when you don't want a custom card. Icons/labels are positioned by percentage.

1. In Export, pick target **Picture Elements**.
2. **Copy YAML** → dashboard **Add card → Manual** → paste → **Save**.
3. **Note:** Picture Elements can't render filled polygon rooms — those are skipped (the
   YAML header tells you how many). Use **ha-floorplan** if you need rooms.

### Raw SVG / PNG
- Target **Raw SVG** gives you just the floorplan SVG.
- **Download PNG** rasterises the current design (with the embedded background) to a PNG.

---

## Verify it renders live

After adding the card, toggle one of your lights from the map and confirm the marker
colour follows the entity state, and that any sensor markers show their live value. If a
marker sits slightly off, nudge it in the editor (arrow keys) and re-export — because the
export is embedded, that's just Copy YAML → replace the card contents.

## Plugin API for integrations

Floorplan Studio exposes `window.floorplanStudio` so third-party integrations can register their own
**device sources, actions and style defaults** — no integration-specific code needs to live
in this repository. The bundled HA-registry source (`src/examples/ha-devices.ts`) registers through exactly
this public API and doubles as the reference implementation.

```ts
window.floorplanStudio.registerPlugin({
  id: 'ramses',                 // unique; re-registering replaces (external may supersede bundled)
  apiVersion: 1,
  provides: {
    deviceSources: [{
      id: 'ramses',
      title: 'RAMSES RF / Ramses Extras',          // label in the Devices modal
      description: 'evohome / RAMSES-II devices',
      fetch: async (ws, ctx) => ({                 // live: called with the active HA WebSocket
        topology: { source: 'ramses_extras', devices: [...], areas: {}, floors: {} },
        note: 'optional extra line under the count',
      }),
      parse: (text, ctx) => ({ kind: 'topology' | 'project' | 'error' | 'nomatch', ... }),
    }],
    actions: [{
      id: 'ramses.seed-devices', label: 'Add devices', icon: 'devices', location: 'toolbar',
    }],
    iconMap: { FAN: 'fan', TRV: 'radiator' },       // class token → mdi icon fallback
    markerDefaults: { size: 40 },                    // merged: plugin < user opts < device hints
    stateRulePresets: [                              // appended to imported markers, role-bound
      { entityRole: 'battery', mode: 'stringMatch', match: 'on', color: '#ef4444', animation: 'blink' },
    ],
    css: '/local/my_integration/floorplan.css',      // injected once (card mode: shadow root)
  },
});
```

- **The manifest is data + functions the editor calls** — no DOM refs, no component internals,
  the editor keeps lifecycle control. Unknown `provides` keys are ignored: plugins and the editor
  version independently (`apiVersion`).
- **DeviceTopology** is the neutral model sources return: `devices[]` with `device_id`,
  `device_class`/`group` (free-form display/grouping tokens), `area_id`, `primary_entity`,
  `entities[]` (`{entity_id, domain, role}`), plus optional `icon`/`color`/`kind`/`suggested`
  presentation hints, `actions`/`style`/`visibility` passthrough (per-gesture overrides, e.g. a
  FAN's double-tap opening a custom card — users can still edit per-marker afterwards), and
  `parent` for topology-aware integrations.
- **Events** need no registry — just `addEventListener` on `window`:
  - `floorplan-studio:action` — a plugin action was clicked.
    `detail: {pluginId, actionId, projectId, floorId, selection: string[]}`
  - `floorplan-studio:project-imported` — `detail: {pluginId?, mode, markers, rooms}`
  - `floorplan-studio:plugins-changed` — `detail: {plugins: string[]}`
- **`floorplanStudio.importProject(json, {mode})`** — merge a studio project/fragment into the open
  project in one undo step (`'merge'`, default; floors pair by name, scaled to the canvas) or
  `'replace'` it. This replaces writing to the editor's IndexedDB directly.
- **`floorplanStudio.projects`** — `active()`, `list()`, `get(id)`, `save(p)`, `remove(id)`,
  `open(id)` — the supported way to read/write stored projects.
- **`floorplanStudio.callWS(msg)`** — call the active Home Assistant WebSocket (throws when not
  connected); also `floorplanStudio.registry.*` for introspection and `subscribe(cb)` to be notified
  when the plugin set changes.
